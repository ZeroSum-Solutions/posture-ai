<project_specification>
  <project_name>Posture AI</project_name>

  <overview>
    Posture AI is a markerless, AI-assisted posture and musculoskeletal screening web app for movement professionals. A practitioner captures a client's standing posture from front, side, and back views (webcam OR uploaded photo), and the app computes a clinical battery of posture imbalances — each as an angle deviation from a 0 degree standard plus a risk percentage — then renders a two-page report: an Overall Rating (letter grade S-E + 0-100 deviation score, lower is better) with annotated front/side skeletal diagrams, and a region-grouped list of body imbalances each showing the deviation, a maintain/warning/danger risk bar, behavioral causes, a schematic tight/weak muscle map, and corrective exercises. It tracks change across assessments and exports a branded PDF. It democratizes the assessment science of a $7,000 clinic posture rig (MotiPhysio) into an accessible browser app.

    CRITICAL BUILD CONSTRAINTS (read carefully):
    1. The clinical scoring engine MUST be a PURE, framework-free TypeScript module (no React, no DOM, no network, no MediaPipe import). It takes detected pose landmarks (plain JSON) and returns assessment results deterministically. This is the heart of the app and must have heavy unit-test (vitest) coverage with hand-authored landmark fixtures. Same input -> identical output, always.
    2. Posture angles are pure GEOMETRY computed from landmark coordinates. Risk percentages and the letter grade are DETERMINISTIC clinical thresholds (a tunable config table) — NOT a trained ML model. The only machine-learning component is the pose-landmark detector (MediaPipe), which produces joint coordinates.
    3. Capture supports TWO input modes: live camera AND image/video upload. Build the UPLOAD path FIRST. A test-mode seam must allow injecting landmark JSON directly (bypassing the camera/MediaPipe) so the full results UI and PDF are deterministically testable headlessly with Playwright.
    4. This is a SCREENING tool, NOT a medical diagnosis. A non-diagnostic disclaimer is a required field on every result and report surface. Use screening vocabulary (maintain / warning / danger; optimal / mild / moderate / significant) — never "normal/abnormal/diagnosis".
    5. Backend is Supabase (Postgres + Auth + Storage) with Row-Level Security so a practitioner can only ever read their own clients' data.
    6. HEADLESS AGENT CONSTRAINT: every agent runs headless with no human approver. NEVER use the `Workflow` tool — its mandatory review gate hangs the session. Do NOT spawn sub-agents, Tasks, or orchestration. The initializer MUST create features by calling the `feature_create_bulk` MCP tool directly (multiple calls of up to 50 each). The `<feature_budget>` element below is the authoritative feature count — create exactly that many.

    Audience: physical therapists, fitness/movement professionals, athletic trainers, chiropractors, and ergonomic/wellness coaches. A solo/consumer user is simply their own single client (same data model).
  </overview>

  <core_features>
    <foundation>

    <clinical_scoring_engine>
      - A pure TypeScript module at src/lib/posture-engine/ with NO React/DOM/network/MediaPipe dependencies
      - Input contract: an array of PoseFrame objects (one per captured view), each a map of named landmarks {x,y,z,visibility} in metric world coordinates plus normalized image coordinates and the view label (front | side | back)
      - Geometry utilities: angle-between-vectors, angle-from-vertical/horizontal, signed angles, plane projection, midpoint, all unit-tested against known triangles
      - Compute each of the 10 imbalance metrics from the correct view via geometry (see clinical_reference): deviation in degrees from a 0 degree standard plus a direction label
      - Deterministic risk scoring: map each deviation to a severityPct (0-100) and a zone (maintain 0-33 / warning 33-66 / danger 66-100) via a piecewise-linear ramp driven by per-metric tunable threshold constants in a single thresholds config file
      - Composite scoring: an overallScore (0-100, higher is worse) aggregated from reliable findings and mapped to a letter grade via the engine-owned band table (S 0-3, A 4-7, B 8-20, C 21-55, D 56-87, E 88-100). No population comparison is produced. A per-view severity index is max(1, round(arithmetic mean severity)) over reliable findings for that view (lower is better; null when none are reliable)
      - Confidence gating: each metric's confidence = min visibility of the landmarks it used; if below a reliability floor the metric is flagged reliable:false, zone:"unreliable", and excluded from the overall aggregate. The engine NEVER throws on missing/occluded landmarks — it degrades gracefully
      - Output contract: AssessmentResult { findings[] each {key,label,region,deviation,standard,unit,direction,severityPct,zone,viewUsed,confidence,reliable,landmarksUsed}, overallScore, overallGrade, viewSeverityIndex{front,side}, generatedAt, engineVersion, disclaimer, missingViews[] }
      - Heavy Vitest coverage: for each metric, fixtures at optimal/warning/danger with hand-computable expected deviation, zone, and severityPct (tight epsilon); exact grade-boundary tests; a low-visibility fixture asserting unreliable + exclusion; composite grade and view-severity determinism
    </clinical_scoring_engine>

    <capture_pipeline>
      - Image/video UPLOAD capture for front, side, and back views (build this BEFORE live camera): drag/drop or file input, JPEG/PNG, thumbnail preview, retake; front + side required, back optional
      - MediaPipe PoseLandmarker provider (singleton, lazy-loaded, IMAGE mode) that runs on a captured frame and returns landmarks; an adapter converts MediaPipe's indexed landmark array into the engine's named-landmark PoseFrame (the magic index->name map lives here, never in the engine)
      - Test-mode seam: when NEXT_PUBLIC_POSTURE_TEST_MODE / ?testMode=1 is active, the capture stage returns an injected PoseFrame from a window hook or committed fixture instead of invoking MediaPipe, so the engine + UI + PDF run for real headlessly
      - Live webcam capture (added AFTER upload): getUserMedia preview, on-screen alignment plumb-line + silhouette guide, a fit check that highlights when required landmarks are visible, 3-2-1 auto-capture, freeze to canvas -> same PoseFrame as upload. Graceful fallback if camera permission denied
      - Persist per view: the captured image (to Supabase Storage) and the extracted PoseFrame JSON (to the capture row) so assessments are reproducible/re-scorable
    </capture_pipeline>

    <authentication>
      - Practitioner sign-up and sign-in with email/password and Google OAuth (Supabase Auth)
      - Auth callback route exchanging the OAuth code for a session

    <assessment_flow>
      - Guided new-assessment wizard: (1) select/confirm client, (2) capture/upload front+side+back, (3) processing, (4) results
      - Submission API: validates practitioner auth, creates an assessment row (status processing), uploads the three images to Storage, writes capture rows with their PoseFrame JSON
      - Scoring application: run the pure engine on the captured PoseFrames, write one assessment_findings row per imbalance, write the composite deviation score, grade, and scoring-engine version onto the assessment, derive exercise_recommendations deterministically, set status complete
      - Processing screen polls assessment status and redirects to results on complete (error state with retry on failure)
    </assessment_flow>

    <results_report_ui>
      - Overall Rating panel: large letter-grade ring (S-E) with the 0-100 deviation score on a lower-is-better maintain->warning->danger gradient bar, plus the exact grade-band reference table (S 0-3, A 4-7, B 8-20, C 21-55, D 56-87, E 88-100)
      - Annotated skeletal sheet: front and side skeleton template diagrams (SVG) with computed red angle markers + directional arrows for the relevant imbalances and the client's captured photo shown as an inset. A footnote clarifies the skeleton illustration is schematic and not the literal measured angle; no population percentile or rank is claimed
      - Region-grouped body-imbalance cards (groups in order: Head/Shoulders, Spine, Pelvis, Leg) — each card shows the imbalance name, deviation vs standard 0 degrees with direction, a maintain/warning/danger risk bar with the severity %, and the "behavior fixes and causes" text
      - Schematic muscle map per imbalance: a front/back body SVG that highlights tight muscle groups in red and weak muscle groups in blue for the selected imbalance, plus named tight/weak muscle lists
      - Recommended corrective exercises per assessment (accordion: name, category, instructions, sets/holds)
      - Every results surface shows the non-diagnostic disclaimer
    </results_report_ui>

    <pdf_report>
      - A two-page, client-ready branded PDF via @react-pdf/renderer rendered client-side:
        Page 1 = client header + Overall Rating (stored grade, deviation score, current-version band table) + annotated front/side skeletal diagrams + a notes area.
        Page 2 = region-grouped imbalance list, each with deviation, risk bar, causes, tight/weak muscles, and recommended exercises.
      - A non-diagnostic disclaimer on every page footer
      - Before/after delta columns when a prior assessment for the same client exists
      - Generation route uploads the PDF blob to a private Storage bucket (service-role) and records a reports row; report page previews via iframe and offers download
    </pdf_report>

    <progress_tracking>
      - Per-client trend charts (Recharts): each imbalance's severity % and the overall grade over time, with maintain/warning/danger reference-area zones
      - Before/after deltas between assessments
      - Dashboard: client count, assessments this week, recent activity, "New Assessment" CTA
    </progress_tracking>

      - Browsable exercise library page (filter by category)
