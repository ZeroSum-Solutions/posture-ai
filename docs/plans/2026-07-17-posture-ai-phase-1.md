## Goal
Warn the practitioner when a capture is too blurry or badly exposed, BEFORE
analysis — as soft warnings that never block submit — closing the
"lighting/blur checks" follow-up deferred by the 2026-06-12 lever-1 design (§8).

## Core design decision (v2 — resolves audit r1 #G1/#G3/#G4/#S2/#S3/#S5)
Pixel metrics are computed at **image-acquisition time**, from canvases that
already exist, never by re-decoding the JPEG URL:
- **Camera:** in FullScreenCapture.tsx the shutter canvas holds the raw frame
  before `toBlob` (:436). Downscale it via GPU `ctx.drawImage` onto a small
  offscreen canvas (width = CALIBRATED_SCALE from T1b, ≤480), `getImageData`
  on the SMALL canvas only, score synchronously, attach the result to the
  capture object handed up via `onCameraCapture`.
- **Upload:** `normalize-upload.ts` already draws every upload to a canvas
  (:26-34). Add the same bounded downscale+score there; return the result
  alongside the data URL.
Consequences: no second JPEG decode (the audit's contention/jank objections),
ALL metrics run on a bounded ≤480-wide sample (perf objection), and
`runPreflight` gains **no new await** — the merge is synchronous, so the
staleness-token flow at page.tsx:206/229/250 is untouched (race objection).
These are the exact canvas APIs normalize-upload already runs on every upload
in production Safari — no new browser-API surface (WebKit objection #S10).

## Product constraints (verified against code)
- Pixels exist only client-side pre-submit (landmarks-only payload, page.tsx:294).
- Soft warnings only; the sole hard block stays `no_person`. Fail OPEN on any
  compute error: try/catch at both acquisition sites → `pixelQuality: null`;
  merge treats null as "no pixel warnings"; `modelError` never set by sampling.
- Do NOT touch lib/pose/quality.ts, quality-score.ts, or the frozen
  lib/capture/shutter-gate.ts. New module = lib/capture/pixel-quality.ts.
- Warning copy: "sentence — corrective action." style; banned stems checked
  MECHANICALLY: add `'lib/capture'` to the ui-vocabulary sweep roots (T5).
- Thresholds are ENGINEERING DEFAULTS (documented as such) until Tier B data
  exists. Both acquisition sites sample BEFORE this app's JPEG re-encode (camera
  shutter canvas; normalize-upload canvas pre-toDataURL) — but an uploaded file
  is typically already camera-compressed at source, so the calibration matrix
  (T1b) still spans both source sizes (720px camera-like, 1600px upload-like)
  and both provenance kinds (raw synthetic + JPEG-decoded fixtures).

## Tasks (ordered; each criterion is a command that must exit 0)

### T1 — Pure pixel-quality scorer (TDD)
`lib/capture/pixel-quality.ts`: `assessPixelQuality(img: PixelSample): PixelQualityResult`
where `PixelSample = { data: Uint8ClampedArray (RGBA), width, height }` —
already downscaled by the caller; the scorer NEVER resizes. Computes:
- luma (Rec.601) mean + fraction clipped dark (<16) / bright (>239);
- sharpness: variance of a 3×3 Laplacian over luma.
Returns `{ sharpness, lumaMean, darkClip, brightClip, warnings: string[] }`.
Copy: "Photo looks blurry — hold the camera steady and retake." / "Photo is too
dark — add more light and retake." / "Photo is overexposed — reduce direct light
and retake." Thresholds as named consts referencing T1b calibration output.
Also exports pure `mergePreflightQuality(frameQuality, pixelQuality|null)`:
ok+pixelWarnings→'warnings'; warnings→concatenated (pixel last); 'no_person'
unchanged; null pixelQuality → frameQuality verbatim.
Tests: synthetic patterns pin scorer behavior + boundaries + purity + empty
input throws; merge-helper table incl. null (fail-open) and no_person cases;
micro-bench: scoring a max-size 480×640 sample completes < 250ms.
**Verify:** `npx vitest run lib/capture/pixel-quality.test.ts` → exit 0.

### T1b — Calibration + labeled fixture matrix (kills circularity, #S4/#S7)
`scripts/calibrate-pixel-quality.mjs` (node, committed): builds the labeled
matrix from the three real e2e photos (front/side/back_standing.jpg) plus
degraded derivatives generated by `scripts/generate-degraded-fixtures.mjs`
(committed; pinned operations: gaussian blur σ=3 px at native res; exposure
×0.35 dark / ×2.2 bright with clamp; pure-JS on RGBA arrays — no new deps,
reuses the decode helpers already vendored for scripts). Evaluates scales
{160, 320, 480}; selects the smallest scale where EVERY sharp/blurred pair
separates by ≥2× Laplacian-variance margin at BOTH camera-like (720px) and
upload-like (1600px) source sizes. Writes
`lib/capture/pixel-quality.calibration.json` (scale + thresholds + per-fixture
values). Acceptance is pinned by `lib/capture/pixel-quality.matrix.test.ts`:
**0 warnings on all normal fixtures (FP ceiling) and the correct warning on
every degraded fixture**, loading the committed JSON + committed fixtures.
**Verify:** `node scripts/calibrate-pixel-quality.mjs --check` → exit 0 (JSON
up to date) AND `npx vitest run lib/capture/pixel-quality.matrix.test.ts` → 0.
