## What is established

- Offline persistence is deliberately limited to owned session mutations: set actuals, conditioning actuals and session completion. It does not claim a general offline application or offline profile/program editing.
- A saved-on-device mutation remains visibly distinct from a server acknowledgement. Ambiguous transport failures keep the immutable envelope; validation rejection removes only that entry; revision conflict waits for explicit discard.
- Direct account replacement without logout deletes the prior actor's actual IndexedDB entry and does not send its request ID as the new actor. The current spec SHA-256 is `5d2284b6…`, matching its proof manifest.
- Coach revocation keeps the assignment mode `coach_assigned`, ends future authority, preserves server history, and clears only session IDs captured in the transaction-bound receipt. The cleanup accepts the complete unique list, including more than 128 sessions.
- Subject erasure is owner/AAL2-only, durable-receipt retry is idempotent, and a late set write cannot recreate the erased session. Linked-client erasure removes the bridge and coach access while retaining athlete-owned history.

## Remaining verification

The smallest consequential addition is one guarded lifecycle replay browser spec with a real UI-created pending mutation and three isolated cases:

1. expire its assignment, reconnect, receive `assignment_expired`, clear only that session scope, and observe no later replay;
2. erase the linked client, preserve athlete-owned history, end coach authority, and deny the old coach envelope without transferring it to the athlete;
3. erase the subject, clear that subject's local queue, deny exact replay, and verify no server row is resurrected.

Each case should retain the request envelope and server response, assert the IndexedDB scope before and after, count network attempts after an `online` event, and bind its source hash to the terminal Chromium and WebKit reports. A separate current-source rerun of `training_revision_locking_race.mjs`, with its hash recorded beside the output, would close the DA-02 provenance gap. Physical-device, browser-crash-without-auth-event and production multi-tenant validation remain outside this local proof.
